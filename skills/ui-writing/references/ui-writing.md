# UIラベルの判断基準

公開されているUIライティングガイドを参考に、Atlasの業務画面で共通して使える判断をまとめたもの。特定製品の名称、ページタイトル、監査ログ、複製名の規則は採用しない。

## 要素ごとの文法

| 要素 | 書き方 | Atlasでの例 |
| --- | --- | --- |
| ボタン | 操作を表す動詞の終止形 | `戻る`、`取り消す` |
| サ変動詞のボタン | 語尾の`する`を省略 | `保存`、`削除`、`通知を表示` |
| 対象を示すボタン | `対象を操作`と書く | `契約を変更` |
| 画面タイトル・項目名 | 名詞で書く。対象を示す場合は`の`を使う | `契約の変更`、`契約席数` |
| 説明文 | 敬体で、体言止めにせず動詞まで書く | `選択したプランを契約内容に反映します。` |
| テキストリンク | `こちら`を避け、移動先を具体的に書く | `導入方法を見る` |

## 移動と一覧

- 具体的な場所へ移動するときは`に`を使う。例: `契約一覧に戻る`。
- 前後など相対的な位置へ移動するときは`へ`を使う。例: `前へ`。
- 表であることが明らかな見出しには、原則として`一覧`を重ねない。

## レビュー

- コンポーネント名ではなく、利用者の目的を表しているか。
- 同じオブジェクトを`契約`、`プラン情報`など複数の語で呼んでいないか。
- ボタンを押した後に起きることを予測できるか。
- 実表示、コード例、アクセシブルネームが同じ意味になっているか。
