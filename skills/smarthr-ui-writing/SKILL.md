# SmartHR UI Writing

日本語のUI文言を新しく書くとき、または既存文言を直すときに使う。SmartHR固有の製品用語やブランド規則をAtlasへ持ち込まず、公開ガイドの判断原則だけを参照する。

## 進め方

1. 文言が置かれる要素と、利用者が次に行う操作を確認する。
2. [UIラベルの判断基準](references/ui-writing.md)を読み、要素に合う文法で書く。
3. 同じ対象を別の語で呼んでいないか、実装都合のコンポーネント名を見せていないか確認する。
4. コード例と実画面の文言を揃える。
5. 画面上で前後の文脈と一緒に読み、短さより操作結果のわかりやすさを優先する。

## Atlasで優先すること

- ボタンは動詞の終止形で書く。`追加する`や`削除する`のようなサ変動詞は`追加`、`削除`とする。
- 対象を明記するボタンは`契約を変更`のように助詞`を`を使う。
- 画面タイトルと項目名は名詞、説明文は敬体で動詞まで書く。
- CTAは、押した後に起きることを表す。`ダイアログを開く`のような実装の説明にしない。
- 導入、画面操作、比較説明を同じ「試す」でまとめない。
- デザインシステムの用語は`DESIGN.md`と`design/`の表記に合わせる。
- SmartHRのガイドを絶対規則として扱わない。利用者にとってわかりやすい表現を選ぶ。

## 対象外

ブランドコピー、広告見出し、長文記事の文体は対象外。SmartHRのページタイトル、監査ログ、複製名などの製品固有規則も転用しない。
